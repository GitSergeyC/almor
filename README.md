# Будильник с защитой от отключения и группами

Реализация Этапов 1–4 из плана: стандартный будильник, группы,
задания для пробуждения, защита от отключения с эскалацией
после принудительной перезагрузки.

## Готовый APK

Каждый push в `main` запускает сборку на GitHub Actions. Готовый APK
лежит во вкладке **Actions** → последний запуск → раздел **Artifacts** →
`alarmclock-debug-apk`. Скачивается zip, внутри `app-debug.apk`.

Сборку можно запустить и вручную: Actions → Build APK → **Run workflow**.

## Как запустить локально

Проект собирается только локально — нужен Android SDK и доступ в сеть
для загрузки зависимостей.

1. Открыть папку в Android Studio (Ladybug или новее).
2. Studio сама предложит сгенерировать Gradle Wrapper — согласиться.
   Либо в терминале: `gradle wrapper --gradle-version 8.9`.
3. File → Sync Project with Gradle Files.
4. Запустить на **реальном устройстве**. Эмулятор не воспроизводит
   поведение Doze и убийц процессов, ради которых половина этого кода написана.

Если Studio ругается на версии AGP/Kotlin — обновите их в `build.gradle.kts`
через встроенный ассистент, остальной код от этого не зависит.

## Ключевые архитектурные решения

**Регистрируется только ближайший будильник.** Не все сразу. После срабатывания
расписание пересчитывается. Экономит системные слоты и делает отладку возможной.

**Группа не перезаписывает личные флаги.** Эффективное состояние =
`alarm.enabled && group.enabled`. Пользователь выключил группу и включил обратно —
получил ровно то, что было. Это отдельно проверено в `AlarmRepository.setGroupEnabled`.

**Сервис и Activity разделены.** Убили экран задания — звук продолжается,
сторож поднимает экран через 2 секунды.

**Незакрытое событие в журнале = перезагрузка во время звонка.**
Единственный способ обойти защиту — принудительный ребут. `BOOT_COMPLETED`
находит запись с `dismissedAt IS NULL` и поднимает звонок с усложнённым заданием.

**Аварийный выход обязателен.** Через 5 минут появляется кнопка экстренного
выключения. Без неё приложение — блокировщик устройства, и это причина
отклонения в Google Play.

## Границы возможного

Полностью заблокировать выключение устройства обычное приложение не может.
Удержание кнопки питания 10–15 секунд и Safe Mode неперехватываемы на уровне
приложения. Компенсация — эскалация после перезагрузки, как выше.

Уровни STRONG и MAXIMUM требуют службы доступности. Без неё приложение честно
деградирует до BASIC и показывает это в UI (`GuardAvailability`).

`./gradlew test` — покрыт `NextTriggerCalculator`, включая весенний скачок DST,
осеннее наложение, 29 февраля и пропуск одного срабатывания.

## Перед публикацией в Google Play

1. Форма обоснования AccessibilityService: писать, что служба активна только
   во время звонка (`AlarmAccessibilityService.guardLevel`), данные не собирает.
2. Демо-видео работы защиты.
3. Data Safety: приложение не передаёт данные наружу.
4. Device Admin придётся обосновывать отдельно — рассмотрите вариант сделать
   уровень MAXIMUM опциональным, чтобы не блокировать релиз.
